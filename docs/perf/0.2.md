# Performance: Blocksy 0.2.0

Measured 2026-10-30 with `pnpm bench` (5 runs, medians shown).

## Machine

| | |
| --- | --- |
| OS | Windows_NT 10.0.26300 |
| CPU | AMD Ryzen 5 7430U with Radeon Graphics (12 threads) |
| RAM | 15 GB |
| GPU | AMD Radeon (TM) Graphics |
| Screen | 2560x1440 at 1.5x |

## Results

| What | Result | Budget | |
| --- | --- | --- | --- |
| Cold start to Home | 1312 ms | 2500 ms | ✅ pass |
| Frame time, median | 16.7 ms | | |
| Frame time, 95th percentile | 16.8 ms | 33.3 ms (30 fps) | ✅ pass |
| Memory, whole app (peak) | 450 MB | 600 MB | ✅ pass |
| JS heap | 33.8 MB | | |
| Block preview ready (first open) | 818 ms | 1000 ms | ✅ pass |
| Frames drawn by an idle 3D view (2 s) | 0 | 0 | ✅ pass |

Cold start counts from the Rust process starting to Home being painted (two frames after first render),
with a fresh WebView2 data folder each run (a true cold start).
The frame times cover a scripted workout: opening the build log, streaming 5,000 log lines,
the New project and Settings dialogs, and switching pages. Memory adds up blocksy.exe and its
WebView2 processes (private working set, as in Task Manager).
The 3D rows open a project with 20 blocks in the editor, time until the first block's preview is drawn
(WebGL start, shaders, texture), then count frames while it sits untouched for 2 seconds (render on demand).

> Background CPU load was about 80% when these runs started (other apps open), so cold start is noisier than
> usual; a quiet run the same evening measured 1093 ms (0.1: 1096 ms). Memory is higher than 0.1 (320 MB)
> because this bench also opens a 3D block preview and a 20-block project; see ADR 0008.
> The block preview is helped by an idle preload after start-up (3D code + a WebGL warm-up), and a pixel
> loader shows within 100 ms whenever it is still getting ready.
