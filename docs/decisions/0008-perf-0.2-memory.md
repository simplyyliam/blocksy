# 0008: Memory rises in 0.2 because the bench now opens a 3D view

- Status: accepted
- Date: 2026-10-30

## Context

Plan section 4.1: a regression of more than 10% against the previous release fails the
definition of done until fixed or explained in an ADR. `docs/perf/0.2.md` shows peak memory
of about 410-450 MB across runs against 320 MB in 0.1 (+30-40%), still under the 600 MB budget.
Cold start on a quiet machine (1093 ms vs 1096 ms) and frame times (p95 ~17 ms vs 33.3 ms) did not regress.

## Decision

Accept the increase, because the bench measures more than before:

- 0.2's bench opens a project with 20 blocks in the project editor and shows a live 3D block
  preview. That starts a WebGL context, and WebView2 adds a GPU process whose memory counts
  in the whole-app total. 0.1 had no 3D view and no open project in the bench.
- What was fixed rather than accepted: the first version of the preview used drei
  `ContactShadows` (extra render targets and blur passes). Replacing it with a single
  gradient plane cut peak memory by roughly 100-180 MB in the same bench.
- The 3D code is lazy-loaded (not part of cold start) and preloaded when a project opens.

## Consequences

- 0.2 is the new baseline for memory: 0.3 is compared against the 0.2 report (450 MB).
- Model Studio (0.5) must keep one shared WebGL context per page and dispose it on leave,
  or memory will climb with every 3D view.
