# 0010: Block preview time in the 0.3 bench

- Status: accepted
- Date: 2026-11-04

## Context

Plan section 4.1: a regression of more than 10% against the previous release fails the definition of
done unless it is fixed or explained in an ADR. In `docs/perf/0.3.md`, "Block preview ready (first open)"
is 1192 ms (budget 1000 ms). The 0.2 report (2026-10-30) recorded 818 ms.

## What was measured

| Build | Date | Preview ready, median | Runs |
| --- | --- | --- | --- |
| 0.2 (report) | 2026-10-30 | 818 ms | 1335, 817, 770, 818, 917 |
| 0.2 code (`main`), re-benched | 2026-11-04 | 1158 ms | 1126, 785, 1165, 1158, 1176 |
| 0.3 branch | 2026-11-04 | 1192 ms | 1196, 1199, 1192, 825, 1174 |

v0.3 does not touch the 3D path (`packages/model-studio`, the block canvas, the idle preload).

## Decision

- The slower preview comes from the machine's state that day (the unchanged 0.2 code shows it too),
  not from v0.3. Against the same-day 0.2 baseline the change is +3%, under the 10% line.
- The budget and the bench stay as they are. A run that waited for idle before timing gave the same
  result, so the method was not changed.

## Consequences

- Liam re-runs `pnpm bench` on a quiet, freshly restarted reference machine. If the preview is back near
  0.8 s, `docs/perf/0.3.md` is updated with that run. If both builds stay near 1.2 s, the cause is outside
  Blocksy (GPU driver, power mode) and is investigated before v0.5, when Model Studio leans on 3D far more.

## Update (same day): found and fixed

A CPU profile showed the time was not 3D at all: opening any element blocked the page for ~700 ms
rendering the canvas backdrop (Magic UI DotPattern: one `motion.circle` per dot, ~2,400 of them).
Canvases now use `CanvasBackdrop` (stock Magic UI GridPattern, one SVG `<pattern>`, same look).
Block preview ready: 733 ms (budget 1000). This also explains the 0.2 re-bench: the same backdrop was
already there; the editor canvas is wider on this screen than when 0.2 was measured.

Left open: the idle-3D row counted 8 frames in 2 of 5 runs (0 in the others), probably resize frames
while the inspector slides in. To fix in v0.4 (redraw only once the inspector's width animation ends).
